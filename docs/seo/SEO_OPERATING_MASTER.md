# 우나어 SEO 운영 마스터

작성일: 2026-07-28

## 1. 최상위 판정

우나어 SEO는 "많은 URL 색인" 전략을 폐기하고, "핵심 자산 화이트리스트" 전략으로 전환한다.

현재 문제는 콘텐츠 부족이 아니다. sitemap 7,577개 URL 중 대부분이 자동 발행 커뮤니티 글이고, 최근 90일 비브랜드 정체성 클릭은 사실상 미미하다. Google에는 우나어가 "45~65 여성의 갱년기·관계·인생 2막 고민 커뮤니티"가 아니라 "정체성 없는 대량 게시판"처럼 보일 위험이 크다.

## 2. SEO 목적

Google이 우나어를 다음 주제의 신뢰 가능한 커뮤니티로 이해하게 만든다.

- 갱년기, 폐경, 완경
- 50대 여성 건강 변화
- 부부관계, 남편, 시댁, 자녀 고민
- 외로움, 빈둥지
- 50대 여성 일자리, 재취업, 알바
- 인생 2막, 은퇴, 연금, 건강보험, 노후
- 우리 또래 커뮤니티 정체성

## 3. 폐기한 과거 전략

아래 전략은 더 이상 사용하지 않는다.

- 글을 많이 만들수록 SEO가 좋아진다는 전제
- 자동 커뮤니티 글을 기본 index로 두는 방식
- sitemap URL 수를 늘리는 방식
- 연예·잡담 클릭을 SEO 성과로 보는 방식
- 색인 요청만 하면 노출이 좋아질 것이라는 기대
- baseline만 남기고 후속 PASS/FAIL을 기록하지 않는 실험 방식

## 4. 현재 AS-IS 요약

| 항목 | 상태 |
|---|---|
| sitemap | 7,577 URL |
| 커뮤니티 비중 | 약 93% |
| 공개글 | 약 7,320개 |
| 자동 발행 비중 | 약 99% |
| 커뮤니티 300자 미만 | 약 4,214개 |
| 커뮤니티 800자 미만 | 약 92% |
| 최근 90일 클릭 | 브랜드/연예/잡담 의존 |
| 정체성 쿼리 | 노출 적고 순위 낮음 |

## 5. 정상인 것과 아닌 것

정상으로 본다.

- robots.txt 기본 허용
- apex 도메인 canonical 기준
- www -> apex 리디렉션
- 커뮤니티 CUID/slug canonical 가드
- 레거시 아임웹 정리
- 커뮤니티 DiscussionForumPosting JSON-LD
- 매거진 Article/FAQ/Breadcrumb JSON-LD
- 가이드/잡 JSON-LD 기본 구조

문제 또는 미비로 본다.

- 새 자동 커뮤니티 글이 기본 index 후보가 되는 구조
- sitemap에 길이, 반응, 정체성 필터가 없음
- 과거 noindex 범위가 가입인사·이벤트 등 일부에 그침
- /guide 인덱스 라우트 부재
- 페이지네이션 canonical 정리 필요
- 마감 일자리 noindex 정책 필요
- SEO 모니터링 크론 미운영
- 실험 결과 문서화 부재

## 6. 새 기본 정책

### 6.1 기본값

새 자동 커뮤니티 글은 기본 noindex로 본다.

- 사이트 안에서는 노출 가능
- 사용자 댓글/조회/활동에는 사용 가능
- Google 검색에는 즉시 보내지 않음
- sitemap에도 기본 미포함

### 6.2 index 허용 원칙

아래 조건을 통과한 글만 Google 검색 자산으로 본다.

- 우나어 핵심 정체성과 맞음
- 본문이 충분히 길고 얕지 않음
- 검색자가 실제로 찾을 만한 질문/문제와 연결됨
- 중복 또는 출처 의존 느낌이 강하지 않음
- 정치, 성적 자극, 의료 단정, 주식 종목 추천 등 위험 주제가 아님
- 허브 또는 대표 글과 내부링크로 연결할 가치가 있음

### 6.3 화이트리스트 규모

초기 목표는 50~150개다.

Claude 실측의 188개 후보는 참고하되, 창업자 의사결정에 따라 더 엄격하게 130개 안팎까지 줄이는 것을 우선 검토한다.

## 7. 검색에 남길 것

| 분류 | 예시 |
|---|---|
| 갱년기/폐경 | 갱년기 증상, 완경 후 몸 변화, 갱년기 짜증, 불면, 열감 |
| 50대 여성 건강 | 체중 변화, 건강검진, 운동 시작, 식단 |

| 일자리 | 50대 여성 재취업, 알바, 공공일자리, 경력 전환 |

## 8. 검색에서 뺄 것

| 분류 | 처리 |
|---|---|
| 연예인/드라마/이슈 글 | noindex + sitemap 제외 |
| 300자 미만 단문 | noindex + sitemap 제외 |
| 댓글 0 + 무반응 글 | noindex + sitemap 제외 |
| 검색 의도 없는 일상 잡담 | noindex + sitemap 제외 |
| 정치/주식 종목/의료 단정 | noindex + sitemap 제외, 허브 링크 금지 |
| 성적 자극/외도/불륜 중심 글 | noindex + 허브 링크 금지 |
| 마감 일자리 | noindex |
| 중복 URL, CUID, 파라미터 URL | canonical 또는 제외 |

## 9. 정책 함수 설계 방향

구현 시 정책은 한 곳으로 모은다.

예상 함수:

- `shouldIndexPostForSeo(post)`
- `shouldIncludePostInSitemap(post)`

원칙:

- sitemap 포함 여부와 상세 robots 판단이 서로 다르면 안 된다.
- 신규 자동 커뮤니티 글은 기본 false다.
- 예외 허용은 코드 상수 allowlist로 시작한다.
- 예외가 100건을 넘으면 `Post.seoApproved` 같은 명시 필드 추가를 검토한다.
- 대량 적용 전 `SEO_WHITELIST_MODE=off|dryrun|on` 플래그를 둔다.

## 10. 허브 우선순위

| 우선순위 | 허브 | 목적 |
|---|---|---|
| P0 | 갱년기/폐경 허브 | 우나어 검색 정체성의 1번 축 |
| P0 | /guide 인덱스 | 이미 효율 좋은 가이드 자산 회수 |
| P1 | 인생 2막/일자리 허브 | 재취업, 알바, 연금, 건강보험 연결 |
| P1 | 부부·가족관계/외로움 허브 | 관계·빈둥지·외로움 경험글 연결 |

허브는 단순 목록이 아니다. 소개문, 타겟 쿼리, 대표 매거진, 대표 경험글, Breadcrumb, CollectionPage/ItemList JSON-LD, 홈/보드 진입 링크를 포함해야 한다.

## 11. 실행 순서

| 순서 | 작업 | 목적 | 상태 |
|---|---|---|---|
| 1 | PR-0 SEO 운영 문서 | 세션 변경 시 기준 고정 | 이 문서 |
| 2 | PR-A 기술 정규화 | /guide, canonical, 마감 JOB, indexing URL 정리 | 일부 시작 |
| 3 | PR-E 관측 장치 | 주간 GSC 스냅샷/BotLog/실험 문서화 | 필수 |
| 4 | PR-C 허브 | 갱년기 허브 + /guide 인덱스 | 대기 |
| 5 | PR-B1 신규 noindex | 앞으로 새는 구멍 차단 | 대기 |
| 6 | PR-D 대표글 보강 | 50~150개 제목/본문/내부링크 보강 | 대기 |
| 7 | PR-B2 기존 글 정리 | 기존 수천 URL noindex/sitemap 제외 | dry-run 후 |

PR-B1/B2는 관측 없이 들어가지 않는다. 과거 실패 원인이 "적용 후 판정 부재"였기 때문이다.

## 12. PASS / FAIL 기준

| 작업 | PASS | FAIL |
|---|---|---|
| 기술 정규화 | 기존 정상 URL 4xx/5xx 없음, canonical 일관 | 기존 유입 URL 깨짐 |
| 관측 장치 | 주간 GSC 스냅샷 4주 연속 기록 | 1회라도 누락 |
| 신규 noindex | 새 자동글 sitemap 미포함 + noindex 확인 | 살릴 글이 noindex 됨 |
| 허브 | 8주 내 허브 자체 노출 발생 | thin/미색인 |
| 기존 정리 | 색인 URL 감소, 정체성 쿼리 노출 증가 | 정체성 쿼리 노출 감소 |
| 대표글 보강 | 6개월 내 정체성 쿼리 1페이지 3건 이상 | 변화 없음 |

최종 6개월 목표:

- 색인 후보 URL: 7,577 -> 200~400
- 비브랜드 정체성 클릭: 15 -> 100+
- 정체성 쿼리 1페이지 진입: 3건 이상

## 13. 실험 기록 규칙

SEO 관련 작업은 반드시 실험 문서를 남긴다.

경로:

`docs/seo/experiments/YYYY-MM-DD-{slug}.md`

필수 항목:

- 목적
- 적용 전 baseline
- 변경 범위
- 적용 일시
- 1차 확인일
- 2차 확인일
- PASS 기준
- FAIL 기준
- 실제 결과
- 후속 조치

baseline만 만들고 결과를 남기지 않는 작업은 실패로 본다.

## 14. 세션 시작 절차

SEO 관련 세션은 아래 순서로 시작한다.

1. `git status --short`
2. 이 문서 확인
3. 최신 GSC 28일/90일 확인
4. 최근 실험 문서 확인
5. 현재 작업이 신규 noindex, 기존 정리, 허브, 관측 중 어디에 속하는지 분류
6. 코드 수정 전 dry-run 또는 PASS 기준 먼저 확정
