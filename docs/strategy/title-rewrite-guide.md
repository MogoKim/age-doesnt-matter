## 1. 이 문서의 목적

외부에서 수집한 글의 제목을 **우리 서비스의 커뮤니티 콘텐츠 제목으로 전환**하기 위한 판단 기준을 정한다.

제목 리라이팅은 "예쁘게 다듬기"가 아니다. **오리지널리티 · SEO · 클릭 · 댓글 유도 · 신뢰**를 한 번에 건드리는 작업이다. 제목 한 줄이 이 다섯을 동시에 올릴 수도, 동시에 깎을 수도 있다.

### 이 문서가 쓰이는 곳

| 대상 | 어떻게 쓰나 |
|---|---|
| 모델 프롬프트 | §3 5축, §4 수위, §6 reject 목록을 지시문으로 변환 |
| 자동 reject 규칙 | §6을 코드 규칙으로 변환 |
| 사람 검수 | §3 5축을 채점표로 사용 (5점 만점) |
| 어드민 검수 UI | §7 체크리스트를 화면 문구로 |
| QA | §9 선행조건이 지켜졌는지 확인 |
| 모델 평가 | §10 비교 설계의 채점 기준 |

### North Star와의 연결

> **주간 재방문 참여 유저 수**

제목 리라이팅의 목적은 **클릭 수 증가가 아니다.** 목적은 사용자가

1. **"이 글 내 얘기 같다"** → 읽는다
2. **"댓글 달고 싶다"** → 참여한다
3. **"다음에도 와야겠다"** → 재방문한다

이 세 단계를 만드는 것이다. **클릭만 올리고 셋 중 하나도 못 만드는 제목은 실패다.** 낚시 제목이 정확히 그런 제목이다.

## 2. 기본 원칙

### 대부분 리라이팅한다. 원문 유지가 예외다.

AS-IS 진단(2026-08-14) 결과, **발행 제목은 원문 카페 제목과 100% 동일**했다(표본 12건 전수 일치). 즉 지금은 리라이팅이 아예 없다. 기본값을 뒤집는다.

```
기본값:  리라이팅한다
예외:    아래 5개를 모두 만족할 때만 원문 유지
```

### 원문 유지 예외 조건 (5개 전부 충족)

1. 원제목에 **사람 냄새가 강하고**
2. **본문과 정확히 맞고**
3. 우리 독자에게 **관련성 신호가 있고**
4. **카페 내부 흔적이 적고** (게시판명·카페 은어·공지 잔재)
5. 리라이팅 후보보다 **명백히 좋을 때**

> "명백히"가 핵심이다. 비슷하면 리라이팅 쪽을 택한다. 단, **원문보다 나빠지는 리라이팅은 하지 않는다.** 애매하면 원문을 남기는 게 아니라 **후보를 다시 만든다.**

### 우선 리라이팅 대상

- **너무 짧아 내용 파악이 안 되는 제목** — 실측상 발행글의 13.3%가 10자 이하다
- **밋밋해서 감정이 안 보이는 제목**
- **원 카페 느낌이 강한 제목** — 그쪽 회원끼리만 통하는 말
- **관련성 신호가 약한 제목** — 우리 독자가 자기 얘기인 줄 모르고 지나침

## 3. 좋은 제목의 5축

**5축을 각 0/1로 채점해 5점 만점.** 3.5점 이상이 PASS.

### ① 본문 싱크

제목의 **사건 · 감정 · 관계 · 결론이 본문에 실제로 있어야** 한다.

- 본문에 없는 것은 아무리 그럴듯해도 넣지 않는다
- 원문 제목과 본문이 어긋나면 **본문을 따른다**
- 이 축이 0이면 나머지가 만점이어도 **즉시 reject**

### ② 사람 냄새

실제 커뮤니티 사용자가 쓴 듯해야 한다.

- 너무 반듯한 AI 문장, 뉴스 문장, 블로그 문장 금지
- 완결된 설명문보다 **말하다 만 듯한 문장**이 낫다
- 문법적으로 완벽할 필요 없다. 오히려 완벽하면 의심해야 한다

### ③ 관련성 신호

우리 독자가 **"내 얘기다"라고 느낄 단서**가 있어야 한다.

```
흰머리 · 갱년기 · 폐경 · 남편 · 딸 · 아들 · 시어머니 · 며느리
건강검진 · 무릎 · 소화 · 잠 · 체력 · 은퇴 · 연금 · 생활비
빈 둥지 · 외로움 · 손주 · 인생 2막 · 재취업
```

- **단, 본문에 없는 단서를 새로 넣으면 안 된다.** ①과 충돌하면 ①이 이긴다
- 본문에 있는데 제목에 안 드러난 신호를 **끌어올리는** 것이 이 축의 핵심이다

> AS-IS 실측: 제목에 우리 나이 주제어가 등장하는 비율이 **소스별 0~6.4%**에 불과했다. 본문에는 있는데 제목이 신호를 못 보내고 있다. **여기가 가장 큰 기회다.**

### ④ 댓글 여지

제목만 보고 **경험 공유 · 공감 · 조언 댓글**을 달고 싶어야 한다.

좋은 자산:
- **질문형** — "~해보신 분 계세요?", "다들 어떠세요?"
- **양가감정** — "할까 말까", "좋은데 걱정도 되고"
- **머뭇거림** — "이런 말 해도 될지 모르겠는데"
- **"저만 그런가요?" 계열** — 공감 요청의 정석

> AS-IS 실측: 수집 제목의 **37.6%가 이미 물음표**를 달고 있다. 이건 큰 자산이므로 **리라이팅하면서 질문형을 잃지 않도록** 주의한다.

### ⑤ 원문 충실

원문보다 **명확해지되 왜곡하지 않는다.**

- 과장된 결론이나 해결책을 만들지 않는다
- 원문 화자가 안 한 말을 하게 만들지 않는다
- 정보를 **더하는 게 아니라 드러내는** 작업이다

## 4. 자극 수위 기준

**자극을 금지하지 않는다.** 커뮤니티 제목은 어느 정도 감정과 궁금증이 있어야 한다. 얌전한 제목은 아무도 안 읽는다. 금지하는 것은 **거짓 자극**이다.

### 5분류

| 분류 | 정의 | 판정 |
|---|---|---|
| **건강한 자극** | 본문에 실재하는 감정·긴장을 제목에 올림 | ✅ **권장** |
| **거짓 자극** | 본문에 없는 사건·갈등·결론을 만듦 | ❌ 즉시 reject |
| **날것의 제목** | 구어체·말줄임·감탄·약한 오타가 자연스럽게 살아 있음 | ✅ 허용 (원문 톤 범위) |
| **AI/블로그 제목** | 지나치게 정제된 설명문 | ❌ reject (품질 미달) |
| **SEO 좋고 신뢰 해침** | 키워드 나열, 단정형 문구 | ❌ reject |

### 카테고리별 수위

| 카테고리 | 감정 수위 | 지켜야 할 선 |
|---|---|---|
| **관계 · 가족 갈등** | **높여도 됨** | 집단 일반화·혐오 금지 ("시어머니들은 다") |
| **일상 · 수다** | **높여도 됨** | 날것의 말투 허용 |
| **몸의 변화 · 갱년기** | 중간 | 감정은 살리되 **증상 단정 금지** |
| **건강 · 의료** | 낮게 | **진단·효과 단정 절대 금지** (헌법 ABSOLUTE_ZERO) |
| **돈 · 연금 · 재테크** | 낮게 | **수익 단정·불안 조장 금지** |
| **법률** | 낮게 | **판단 단정 금지** |
| **시사 · 사회** | 매우 낮게 | 정치·갈등 유발 주의 (기존 정치 키워드 가드가 1차 차단) |

### 두 개의 경계선

**클릭 ↑ / 신뢰 ↓ 경계**
> 제목이 약속한 것을 본문이 지키는가? 못 지키면 낚시다.
> 클릭은 한 번 오르고, 신뢰는 영구히 깎인다. North Star에는 마이너스다.

**댓글 ↑ / 싸움 ↑ 경계**
```
✅ "저만 이렇게 예민한가요?"        공감 요청 — 좋다
⚠️ "이런 사람 어떻게 생각하세요?"    심판 요청 — 주의
❌ "요즘 젊은 사람들은 왜 그럴까요"   집단 공격 — 차단
```

## 5. 오타 · 구어체 · 말줄임 기준

### 원칙: **만드는 게 아니라 보존하는 것**

| | 판정 |
|---|---|
| 원문에 이미 있는 자연스러운 오타·말줄임·감탄 | ✅ 보존 가능 |
| 자연스러운 구어체 어미 (~네요, ~거든요, ~인가요) | ✅ 허용 |
| 말줄임 `…` / 감탄 `ㅠ` `ㅋ` — **원문 톤과 맞을 때만** | ✅ 허용 |
| **새 오타를 억지로 만들어 넣기** | ❌ 금지 |
| 원문 이상으로 `ㅋㅋㅋㅋㅋ` 증폭 | ❌ 금지 |
| 20~30대 말투 (`~인 이유`, `~각`, `ㅇㅈ`, `ㄹㅇ`, `찐`, `레전드`) | ❌ 금지 |
| 너무 완벽하게 다듬어 AI 티가 나는 것 | ❌ 금지 |

> **왜 오타를 만들면 안 되나**: 사람 흉내를 내려고 없던 오타를 넣는 건 실패의 전형이다. 독자는 어색함을 정확히 알아챈다. 원문에 있던 것을 **살려두는 것**은 진짜지만, 만들어 넣는 것은 연기다.

## 6. 나쁜 제목 — reject 기준

아래에 하나라도 걸리면 **후보에서 탈락**시킨다.

### 낚시어

```
❌ 충격 · 반전 · 꼭 보세요 · 모두가 몰랐던 비밀 · 이걸 안 보면 손해
❌ 이유는? · 결과는? · 놀라운 · 소름
```

### AI/블로그체

```
❌ "원인과 대처법 완벽 정리"
❌ "~하는 5가지 방법"
❌ "총정리" · "꿀팁" · "완벽 가이드" · "알아두면 좋은"
```

> **실제 사례**: 매거진 경로에 이런 제목이 있었다.
> ```
> title    : 갱년기 두근거림, 심장 이상일까요?          ← 좋다
> seoTitle : 갱년기 두근거림 심장 이상인가요? 원인과 대처법 완벽 정리   ← 나쁘다
> ```
> 뒤에 붙은 `원인과 대처법 완벽 정리`가 정확히 우리가 피해야 할 문장이다. 매거진은 성격이 다른 별도 경로지만, **커뮤니티에 이 패턴이 들어오면 안 된다.**

### 키워드 나열

```
❌ "갱년기 불면증 증상 원인 치료"
❌ "50대 여성 건강관리 방법 추천"
```

### 내용 왜곡

```
❌ 본문은 고민인데 제목은 해결책처럼      "갱년기 불면증, 이렇게 해결했어요" (본문엔 해결 없음)
❌ 본문에 없는 가족관계·나이·직업 추정     "50대 주부인데" (본문에 안 나옴)
❌ 원문보다 더 자극적인 사건으로 포장      말다툼 → "이혼 얘기까지 나왔어요"
```

### 단정형

```
❌ 의료: "갱년기엔 이게 답입니다"
❌ 재정: "이 방법이면 노후 걱정 없어요"
❌ 법률: "이건 무조건 승소합니다"
```

### 집단 공격

```
❌ 특정 세대·성별·지역·직업을 싸움 붙이는 제목
```

## 7. 본문-제목 싱크 체크리스트

**제목 후보를 만들 때 반드시 확인한다.** 하나라도 ❌면 후보를 버린다.

```
□ 이 사건이 본문에 있는가?
□ 이 감정이 본문에 있는가?
□ 이 관계가 본문에 명시됐는가?          (추정 금지)
□ 이 결론이 본문에 있는가?
□ 이 질문이 본문 화자의 질문인가?
□ 댓글에서만 나온 정보를 제목에 넣지 않았는가?   (topComments는 참고용, 제목 근거 아님)
□ 원문 화자가 말하지 않은 감정을 넣지 않았는가?
□ 본문보다 제목이 과하게 세지 않았는가?
□ 반대로 제목이 너무 밋밋해서 본문의 감정을 죽이지 않았는가?
```

> 마지막 항목이 중요하다. **과장만 잘못이 아니다. 축소도 잘못이다.** 본문에 서운함이 가득한데 제목이 "남편 이야기"면 그것도 싱크 실패다.

### 본문에서 읽어야 할 신호

```
화자의 고민       무엇이 힘든가
사건             언제 무슨 일이 있었나
감정             서운함 · 억울함 · 불안 · 민망함 · 후련함 (구체 감정어)
관계             본문에 명시된 것만
시간대 · 계절성    "이 새벽에", "휴가 중" — 강력한 관련성 신호
질문 여부         물음표 · 조언 요청 → 댓글 여지
댓글 포인트       양가감정 · 경험 공유 요청
원문 제목과 본문의 어긋남 → 본문을 따른다
```

## 8. 원제목 보존 원칙

### 원제목은 반드시 보존한다.

| 이유 | 설명 |
|---|---|
| **출처 추적** | 어느 글에서 왔는지 |
| **중복 판정** | 리라이팅 후 제목만으로는 같은 원문인지 알 수 없다 |
| **rollback** | 되돌릴 원본이 없으면 되돌릴 수 없다 |
| **품질 비교** | 원문 대비 나아졌는지 판단 |
| **모델 평가** | 모델·프롬프트별 비교의 기준선 |
| **운영 감사** | 나중에 "왜 이렇게 바뀌었나" 답할 수 있어야 한다 |

### 절대 규칙

```
🚫 CafePost.title 을 덮어쓰지 않는다.
```

`CafePost`는 원문 보관소다. 현재 코드도 *"원문(CafePost)은 미수정"* 원칙을 지키고 있다. 리라이팅이 이 원칙을 깨면 안 된다.

### 필요한 계층 (설계만 — 실행하지 않는다)

발행 제목을 바꾸려면 원제목/리라이트 제목을 분리할 계층이 필요하다.

| 후보 | 용도 | 비고 |
|---|---|---|
| `CafePost.rewrittenTitle` | shadow 후보 저장 (M5) | 고객 노출 0으로 평가 가능 |
| `Post.originalTitle` | 발행 시점 원제목 보존 (M6) | rollback·감사용 |
| `Post.cafePostId` (기존) | 원문 역추적 | 보조 수단. 단독 의존 금지 |

> ⚠️ **DB 변경은 이 문서에서 설계만 언급하고 실행하지 않는다.** 실제 반영은 `/prisma-guide` 절차(pg 모듈 직접 SQL + `information_schema` 검증)로 창업자 승인 후 별도 진행한다. `prisma migrate`·`db push`는 이 프로젝트에서 사용하지 않는다.

## 9. 구현 전 선행조건 (전부 충족 전에는 발행 경로 적용 금지)

AS-IS 진단에서 확인된 **실제 코드 의존성**이다. 이걸 그냥 두고 리라이팅을 켜면 조용히 망가진다.

### ① 중복 판정 보강 — **필수**

현재 중복 판정은 **발행 제목의 편집거리(≤5)** 기준이다. 리라이팅하면 같은 원문에서 나온 두 글의 거리가 5를 훌쩍 넘어 **중복이 그대로 통과**한다.

```
→ 중복 판정을 원제목 또는 cafePostId 기준으로 옮긴다.
```

### ② noindex / SEO 회귀 테스트 — **필수**

구글 전용 noindex 판정이 **제목 + 본문**을 함께 본다. 리라이팅으로 주제어가 빠지면 색인되던 글이 조용히 noindex로 뒤집힐 수 있다(반대도 가능).

```
→ 제목 변경 전후로 noindex 판정이 뒤집히는지 회귀 테스트를 붙인다.
→ 네이버 일반 robots는 영향받지 않지만, 확인 없이 넘기지 않는다.
```

> 참고: sitemap은 `slug`만 사용하고 제목을 쓰지 않는다. slug는 생성 시 1회 확정되므로 **발행 후 제목을 바꿔도 URL은 변하지 않는다.**

### ③ 원제목 보존 구조 — **필수**

§8의 계층 없이 발행 경로에 적용하지 않는다.

### ④ shadow 또는 검수 단계 선행 — **필수**

고객 노출 0 상태에서 먼저 평가한다. 여우야 shadow 온보딩과 같은 패턴이다.

### ⑤ 기존 발행글 일괄 변경 금지 — **필수**

이미 색인된 글의 제목을 한꺼번에 바꾸지 않는다. **신규 발행분 또는 제한된 범위**부터 간다. 네이버 유입은 생존 조건이므로 마지막에 건드린다.

## 10. 저가 모델 재검증 기준

### 전제 — 판단을 굳히지 않는다

과거 Haiku 등 저가 모델 기반 본문 리라이팅에서 **AI 티가 강하다는 판단**이 있었다. 다만 그것이 **모델 한계인지, 프롬프트·평가 기준·출력 제약의 문제인지 확정된 적이 없다.**

```
→ 저가 모델을 배제하지 않는다.
→ 제목 리라이팅에서 모델 급과 설계를 분리해 다시 시험한다.
```

### 비용은 제목 단위에서 큰 제약이 아니다

로드맵 M4의 "비용" 항목은 **본문 전체 변환** 기준이다. 제목은 입출력이 짧아 자릿수가 다르다.

```
제목 단위:  큰 제약 아님 → 저가 모델 재검증을 적극 검토
본문 전체:  여전히 제약 → M6에서 단계적으로만
```

### 입력에 넣을 것

```
원제목
본문 일부 또는 요약           (도입 감정 + 마무리 질문이 핵심 구간)
source · category · boardName
engagement                   댓글 수 · 공감 수 · 조회 수
감정 · 주제 신호              desireCategory · emotionTags · psychInsight (이미 DB에 있음 — 재활용)
금지 표현 / 허용 표현 목록      §5 · §6
자극 수위 지시                카테고리별 (§4)
좋은 예 / 나쁜 예             실제 제목 사용
```

> 감정·주제 신호는 이미 저장돼 있다. **새로 분석하지 않고 그대로 넣으면** 저가 모델의 부담이 크게 줄어든다. 과거 시도와 달라지는 지점일 수 있다.

### 출력과 선택

```
후보 여러 개 (3개 권장) + 각 후보의 근거 1줄 (본문 어느 부분에서 왔는지)
   → 근거를 강제하면 환각이 줄고 자동 검증이 가능해진다

자동 reject (모델 호출 후 규칙으로)
   · 본문에 없는 명사 유입
   · §6 낚시어 · AI/블로그체 · 키워드 나열 매칭
   · 의료 · 법률 · 재정 단정형 어미
   · 길이 이탈
   · 원제목과 거의 동일 (= 안 바꾼 것)
   · 20~30대 말투

사람 검수: §3 5축 채점 → 3.5점 이상 PASS
```

### 확장 / 후퇴 조건

```
품질 통과 → 요약 · 본문 일부 · 댓글 보정으로 점진 확장 (M6)
품질 부족 → 상위 모델 또는 규칙 기반 + 모델 혼합 검토
어느 쪽이든 → 검증 결과와 이유를 문서·메모리에 남긴다
```

```

## 12. 실제 예시

AS-IS 진단(2026-08-14)에서 확인한 실제 제목이다. 본문 인용은 최소화했다.

### 유지 예외 후보 — 손대지 않는다

| 제목 | 왜 좋은가 |
|---|---|
| **"40대 후반 이후 공무원 입직하신 언니들~ 기운 좀 주세요 ㅠ"** | 5축 전부 통과. 나이·상황·감정·댓글 요청이 한 줄에 다 있다 |
| **"이새벽에 속터져서 잠이 안와요 ㅠ"** | 시간대 + 감정 + 날것. 이미 좋은 제목이다 |
| **"에어컨끄셧나용...?"** | 구어체·오타·말줄임이 자연스럽게 살아 있는 사례. **이런 건 고치는 게 개악이다** |

### 리라이팅 대상

| 원제목 | 문제 | 방향 |
|---|---|---|
| **"소외감"** (3자) | 너무 짧아 맥락 없음. 클릭할 이유가 없다 | 본문의 상황(모임 3년째, 뒷자리 동료)을 끌어와 맥락 보강 |
| **"염색은 어디서 하세요 ?"** | 질문형은 좋으나 관련성 신호가 약함 | 본문에 있는 "흰머리", "15년차"를 검토. **단 질문형은 반드시 살린다** |

> **"염색" 사례가 보여주는 트레이드오프**: 관련성 신호(흰머리)를 넣으려다 질문형(댓글 유도)을 잃을 수 있다. 물음표가 이미 37.6%라는 건 큰 자산이므로 **질문형 보존을 우선**한다. 둘 다 살리는 후보를 먼저 찾는다.

### 커뮤니티에 부적합한 형태

```
"원인과 대처법 완벽 정리" 류   → AI/블로그체. 커뮤니티 제목이 아니다
```

### 제목 문제가 아닌 것

```
"i성향 엄마는 등원길에 누굴 마주치는것도 힘드네욬ㅋㅋ"
```
말투는 훌륭하다. 문제는 **타겟이 어긋난다**는 것이다(등원 = 우리 타겟보다 젊은 층). 이건 제목으로 풀 문제가 아니라 **소스 선별 문제**다. §13 참조.

## 13. 이 문서가 아닌 것

- **구현 지시서가 아니다.** 코드 변경 방법은 여기 없다
- **모델 프롬프트 최종본이 아니다.** 프롬프트는 이 기준을 재료로 별도 작성한다
- **모든 제목을 좋게 바꿀 수 있다는 보장이 아니다.** 후보 전부가 원문보다 나쁘면 원문을 남긴다
- **타겟이 안 맞는 글을 제목으로 살리려는 문서가 아니다**

마지막 항목을 특히 강조한다.

> 수집량 1위 소스에서 **등원 · 고2 · 수능** 같은 학령기 육아 글이 들어오고 있다.
> 이건 제목을 아무리 잘 써도 우리 독자의 글이 되지 않는다.
> **제목은 증상이고, 원인은 소스 선별이다.** 로드맵 M2(소스 다양화)에서 다룬다.
> 제목 리라이팅으로 이걸 덮으려 하면, 잘 쓴 제목으로 안 맞는 글을 파는 셈이 된다 — 낚시와 같은 결과다.
